# <주제> 문서 작업 지침

## 아이디어 기록

- 사용자가 <주제>의 아이디어, 디자인 방향, 구조, 운영 방식에 관한 의견이나 결정을 말하면 `thoughts.md` 끝에 기록합니다.
- 파일 관리, Git 작업, 기록 방식에 관한 요청과 일반적인 진행 질문은 기록하지 않습니다. 이 지침을 논의하는 발언도 제외합니다.
- 사용자의 원문을 보존합니다. 요약, 문장 다듬기, 맞춤법 교정, 어시스턴트의 해석을 추가하지 않습니다.
- 아이디어와 관리 요청이 한 메시지에 섞여 있으면 아이디어에 관한 부분만 원문 그대로 발췌합니다.
- 어시스턴트의 제안과 조사 내용은 별도 문서에 작성합니다. 사용자가 채택하더라도 `thoughts.md`에는 사용자가 직접 말한 내용만 기록합니다.
- 각 기록은 아래 형식을 사용합니다. 시각은 발언 시각이며, 사용하는 시간대를 `thoughts.md` 머리말에 밝힙니다. 발언 시각을 확인할 수 없으면 추정하지 않고, 기록 시각을 사용했다는 설명을 둡니다.
- 기존 기록을 수정하거나 삭제하지 않고 새 기록을 끝에 추가합니다. 사용자가 정정이나 삭제를 요청한 경우에는 그 요청을 따릅니다.

```text
---

YYYY-MM-DD HH:mm:ss

<사용자가 말한 아이디어 원문>
```

## 문서의 구분

- `thoughts.md`는 사용자 아이디어 원문입니다. 논의 중인지 결정됐는지와 무관하게 원문 기록 규칙을 따릅니다.
- `draft.md`에는 논의 중인 설계안, 미정 항목, 어시스턴트의 미채택 제안, 확인할 것, 진행 계획 초안을 기록합니다.
- `design.md`에는 현재 사용자가 채택한 목표, 디자인 철학, 구조만 기록합니다. 채택된 내용도 후속 결정에 따라 바뀔 수 있습니다.
- 주제별 결정 문서를 추가했다면 여기에 파일 이름과 담는 내용을 등록합니다. 결정 문서에는 `design.md`와 같은 규칙을 적용합니다.

## 결정과 논의의 분리

- 한 항목에 결정된 부분과 미정인 부분이 섞이면 분리합니다. 결정된 부분만 결정 문서에 두고, 남은 질문과 대안은 `draft.md`로 옮깁니다.
- 결정 문서에 빈 필드나 미정 목록을 쌓지 않습니다. 값이 결정된 항목만 작성합니다.
- 새 아이디어를 곧바로 결정 문서에 넣지 않습니다. 사용자의 채택 여부와 아직 정할 내용을 `draft.md`에 함께 기록합니다.
- 채택되면 결정 문서에 반영하고 `draft.md`에서는 해결된 논의를 정리합니다. 같은 설계안의 사본이나 변경 이력을 여러 파일에 쌓지 않습니다.
- 사용자가 정하지 않은 수치, 문구, 순서를 임의로 확정하지 않습니다. 예시와 실제 결정을 구분합니다.

## 근거

- 코드, 외부 시스템, 도구의 동작은 확인한 명령, 경로, 링크와 함께 작성합니다.
- 확인하지 않은 동작은 `draft.md`의 "확인할 것"에 둡니다.
- 참고 자료나 다른 사례는 출처와 함께 두고, 채택된 설계로 취급하지 않습니다.
